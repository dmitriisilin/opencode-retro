# opencode-retro

[English](README.md) · [Русский](README.ru.md) · **简体中文** · [Español](README.es.md) · [日本語](README.ja.md)

> `README.md` 的译文。英文版为准（canonical）；若两者不一致，以英文版为准。

**给编码智能体做复盘。** 一个 [OpenCode](https://opencode.ai) v2 插件，把会话中的摩擦——回滚、绕圈、被悄悄放弃的任务、用户的纠正——变成对你这套工作环境（技能、说明文件、工具、代码）的改动建议。

智能体不会从自己的会话里学到东西。想知道它在哪里卡住，唯一的办法是读日志，而日志没人读。`opencode-retro` 替你读，然后带着建议回来。

> **状态：端到端可用，但尚未发布。** 采集、提炼、复核都已完成，并在 OpenCode 2.0.32 上验证过。npm 上目前只有占位版本——先用路径安装。哪些有、哪些还没有，见[路线图](#路线图)。

## 问题

每一次会话，智能体都会撞上同样的墙：

- 某个技能说“跑一下 linter”——可这个项目并不用 linter；智能体跑了，改写了 40 个文件，意识到错了，再把一切回滚；
- 同一条失败的命令被重试四次，而两次之间什么都没变；
- 计划里的一项任务被悄悄放下，理由是“现在做不到”；
- 用户已经第三周在说“不，我们这儿不这么做”；
- 一个能省下 20 步的工具，压根就不存在。

这些全都在日志里。而其中没有一条会进入下一次会话。

## 它做什么

两个循环，有意分开。

### 1. 采集循环 —— 自动，每次会话

插件为每一次工具调用和每一条提示维护一份轻量的**影子日志**（`.retro/sessions/<id>.jsonl`）。不涉及任何大模型，只是追加写入。因此插件不依赖会话历史的压缩——原始轨迹始终可得。一次会话被成功提炼之后，它的日志就会被删除：故事已经由教训本身承载，而每次会话都留一份日志只是在屯货。

模型前面没有检测器，也没有任何规定来界定什么算摩擦。我们试过三个——同一条命令在两次尝试之间毫无改动地重试、一处改动又被撤销、某技能规定的命令随后失败——并且**做了测量**：它们是否改变了结果。并没有。给同一份日志，模型在有和没有这些检测器的情况下都找出了同样的教训（见 `fixtures/ab-anchors/`）。它们真正编码的不是检测，而是“该看什么”的一种看法——而看法属于你能读、也能反驳的提示文件，不属于预先决定模型可以注意到什么的代码。所以它现在就在那里：`.retro/prompts/extract.md` 描述了值得寻找的形态——白做的工作、被撤销的改动、走进死胡同的技能、藏在 “completed” 状态背后的非零退出码、被悄悄放弃的任务、你不得不纠正两次的事——并且明确声明这是一个起点，不是检查清单。

一次会话结束时会被排入队列，而**下一次会话的第一条提示**偿还这笔债：一次干净上下文下的模型调用（不是那个干活的智能体——它会替自己的决定辩护）拿到日志的压缩投影，其中工具输出被裁剪，提示与回答保持完整。它回答一个问题：

> *如果这次会话重来一遍，项目里应该改什么，才能让它走得更短、更直？*

产出是 `.retro/lessons/` 里的一份**教训**清单。

为什么是下一次会话而不是这一次：OpenCode 的 `generate.text` 只有在调用源自某个钩子内部时才会返回，而会话是由事件结束的。所以教训会晚一个会话出现，而一个你再也不会打开的项目则不花任何代价。`/retro` 可以按需把这笔债结清。

### 2. 整合循环 —— 按需，`/retro`

插件读日志，你读建议。它到建议为止：它不会动你的文件。

```
/retro         一条教训 —— 尚未裁决、得分最高的那一条
/retro auto    所有待处理的教训，汇成一份计划，一次批准
/retro check   插件到底在不在工作
```

`/retro` 把教训送进你执行命令的那次会话，形式是一条写给已经在场的智能体的消息：

```
_opencode-retro：先回答一个问题 —— 在这个工作区当前的状态下，这件事是不是已经解决了？
一条教训可能已经躺了好几周，而你了解这个项目；用你平时的方式去核对。……在人类做出决定
之前不要改动任何东西。_

# retro — `lint-skill-no-config`

lint 技能规定要运行 `npx eslint . --fix`，而这个项目跑不了它。

出现于 2 次会话，为此花掉 9 步，置信度 0.9 → 得分 16.2。
上次出现是 3 个会话之前。

_核对之前值得知道：记录于 2026-10-19；此后 `AGENTS.md` 已有改动。_

## 建议的改动
**AGENTS.md** —— 把 lint 的要求改为以仓库中已提交的 ESLint 配置为前提。

## 需要你来决定
这个项目到底应该配置 ESLint，还是应该放弃 lint 这条约定？
```

接下来由你和智能体决定。智能体手里有文件、有历史、有这个项目自己的技能；在“这条教训是否依然成立”这件事上，它比插件更有判断力，而实际上它会去核对那些说法，并找出建议里没提到的后果。决定之后，它用 `retro_decide` 工具把结果记下来——这只是记账。被否决的教训会被记住，不会再次被提出。

`/retro auto` 是同一件事的批量版：所有待处理的教训，按序排列，并给出一份只覆盖仍然成立者的计划，按文件归组。它是为计划模式准备的——读计划、批准一次、开始干。

教训里的建议是一个*提议*，不是一套模式。常见的落点：

- **skill** —— 修正或补充某个 `SKILL.md`，写清这件事在这里实际是怎么做的
- **instruction** —— 给 `AGENTS.md` 的一条事实或约束
- **tool** —— 对人类的一个请求：“缺少 X；没有它，会话 A、B、C 各损失约 N 步”
- **refactor** —— 改动代码库本身以移除这个陷阱，附理由，绝不自动应用
- **other** —— 套不进去；由人类决定

## 教训的格式

```yaml
id: lint-skill-no-config
statement: The `lint` skill assumes eslint; this project has no linter.
evidence:
  - session: a81f
    steps: [41, 58]
  - session: c204
    steps: [12, 19]
cost: 34          # 被这个问题吃掉的步数，跨会话累加
recurrence: 3     # 它出现过的独立会话数
confidence: 0.9
lastSeen: 41      # 它最后一次出现时，该工作区的会话计数
recordedAt: 2026-10-19T15:16:04.134Z
proposal:         # 可选
  target: .opencode/skills/lint/SKILL.md
  change: |
    Before running: check for a lint config (eslint.config.*, .eslintrc*)
    and a `lint` script in package.json. If absent, do not run; report.
ask: Is the linter really unused here? Remove the skill from this project?
status: new       # new | later   （已裁决的会移入 archive/）
```

得分是 `cost × recurrence × confidence × freshness`。新鲜度每过十个没有再次出现的会话就减半，而且是按**会话计，而不是按天计**：如果一天只有一次会话，按挂钟时间衰减会在一夜之间把一切埋掉。复发比一次昂贵的事故更重要：在三次会话里出现过的教训，第四次*还会*出现。

教训的作用域是工作区，并且以**问题而非会话**为键：第二次会话碰上同一件事，只会追加证据并把 `recurrence` 加一，而不是再建一个文件。`lessons/` 里只放未决的问题——裁决会把文件移入 `archive/`，而且任何东西都不会被删除，因为一个被关闭之后又回来的问题，是同一个问题**加上**“那个修法没撑住”这条新消息。它会带着完整的历史重新打开。上限（默认 30）让列表保持简短；超出的部分也进归档。

## 它不是什么

- **不是记忆插件。** 记忆插件会建一个知识库，而智能体必须记得去查它。`opencode-retro` 改的是工作环境本来就会读的文件（`SKILL.md`、`AGENTS.md`）。活在技能里的知识不需要被回忆。
- **不是死循环中断器。** 循环检测器*当下*就把智能体拦住。这个插件负责让这个循环*下一次*不再发生。两者都该用。
- **不是“成功路径”收割机。** 多数自我改进类的技能工具采集的是*成功*了的东西。这个采集的是*没成功*的，而便宜的收益正在那里。

## 教训是局部的，修法可能是局部的也可能是全局的

教训始终属于某个工作区。一条教训是来自某一个项目若干会话的证据，所以它只住在那个项目里，别处都没有：既没有全局的教训仓库，也没有把教训从一个项目晋升到别处的机制。这是刻意的设计。

可能是全局的，是**修法**。有些摩擦关乎这个仓库：一个与它不合的技能、一句在这里并不成立的 `AGENTS.md` 断言。有些关乎你在任何地方的工作方式：你怎么用你的任务追踪系统、你希望分支怎么命名、你带着跨项目走的某条约定。前者属于项目自己的工作环境；后者属于你的全局环境——`~/.config/opencode/AGENTS.md`，或者一个全局技能。

一条教训需要哪一种，是在交接的那一刻决定的——由你和智能体一起，依据这条教训实际说了什么。插件不猜，也绝不会自作主张去改你的全局环境。

## 路线图

| 级别 | 插件做什么 | 人类做什么 | |
|---|---|---|---|
| **L0** | 采集 + 提炼教训 | 手动读 `lessons/` | ✅ |
| **L1** | `/retro` 一次提一条 | 与智能体一起裁决 | ✅ |
| **L1.5** | `/retro auto` 把待处理的全部排成计划 | 一次性批准计划 | ✅ |
| **L2** | 高置信且被确认过 ≥2 次的教训自动应用到一个分支 | 复核这一批 | |
| **L3** | 技能与说明无需复核即应用 | 只看到 `tool` 和 `refactor` 两类请求 | |

级别之间的晋升由插件自己的采纳／否决统计驱动——自治是它挣来的，不是被授予的。

尚未实现：上面那些级别。

## 设计抉择

- **独立的提炼会话。** 干活的智能体是评判自己会话的最差人选。
- **影子日志，而非会话历史。** 已经写下来的东西，压缩吃不掉。
- **摩擦比成功更有价值。** 回滚、重试与纠正更少见，信号也比“这次挺顺”强得多。
- **改文件，而不是加记忆。** 改工作环境已经会读的东西；别增加需要记住的东西。
- **先设人类这道闸。** 自治是后面的级别，有它自己的举证责任。
- **到建议为止。** 你会话里的那个智能体手里有文件、有历史、有这个项目的技能。问它一句*“这还成立吗”*，胜过由插件规定该怎么核对。

## 安装

npm 上目前只有占位版本。把 `opencode.json` 指向一份检出——路径必须是**绝对路径**，相对路径会让会话启动挂住且不报错：

```jsonc
{
  "plugins": [
    {
      "package": "/abs/path/to/opencode-retro",
      "options": {
        // 必填：缺了它 OpenCode 会解析到自己的免费层，而插件不允许使用该层
        "model": { "providerID": "deepseek", "id": "deepseek-flash" }
      }
    }
  ]
}
```

其余选项全部可选：`dir`（默认 `.retro`）、`prompts`、`halfLife`（10 个会话）、`autoLimit`（每次 `/retro auto` 10 条教训）、`maxOutput`、`extractTimeoutMs`、`keepSessions`。

插件写下的一切都在你项目的 `.retro/` 之下，别处都没有——除非你采纳了某个建议。全部是纯文本：

```
.retro/
├── prompts/
│   ├── extract.md       # 归你编辑 —— 什么算一条教训
│   ├── review.md        # 归你编辑 —— 一条教训如何交接
│   └── review-auto.md   # 归你编辑 —— 一批教训如何汇成一份计划
├── sessions/<id>.jsonl  # 原料，提炼完即删除
├── lessons/<id>.md      # 产物
├── archive/             # 已裁决与被挤出的教训
├── selfcheck.md         # 插件在不在工作
└── state.json
```

每个提示文件都在首次运行时由随包的默认版本播种，之后再也不会被写入。解析顺序是项目 → `~/.config/opencode/retro/prompts/` → 随包默认，所以你可以为某一个项目、为你所有项目、或者都不固定某个提示。更新后的默认版本会以 `prompts/updates/<name>.vN.md` 的形式出现，开头写明该文件并未被使用——不会有任何东西替你应用。

留在源码里、不归你编辑的是机械部分：解析器需要的输出格式（`/retro check` 会把它打印出来）、教训字段的顺序，以及记录裁决结果的那条指示。一个不再产出可解析教训的提示会无声地失败——而这正是唯一值得特意防范的失败方式。

### 它在工作吗？

钩子注册成功什么也证明不了：一个写错名字的钩子会注册得很顺利，然后永远不触发。所以 `.retro/selfcheck.md` 断言的不是“已装好”，而是“活着”——做法是把事件流与钩子交叉比对——并且带上它自己的过期规则：

> 如果你此刻正在工作，而 `heartbeat` 已经超过几分钟，那么这个插件没有在运行。

`/retro check` 是主动版本：`ctx` 的接口面、模型连通性、当前生效的是哪一层提示，以及真实输出契约的一次往返。

## 依赖要求

- OpenCode **v2**（`@opencode/plugin` ≥ 2.0；已在 2.0.32 上验证）
- 一个用于提炼的模型，在 `options.model` 里显式指定；便宜的就够了
- 没有运行时依赖
