# opencode-retro

[English](README.md) · [Русский](README.ru.md) · [简体中文](README.zh-CN.md) · [Español](README.es.md) · **日本語**

> `README.md` の翻訳です。英語版が正本（canonical）です。食い違う場合は英語版が正しいものとします。

**コーディングエージェントのための振り返り。** セッション中の摩擦——巻き戻し、同じ場所での空転、放棄されたタスク、ユーザーからの訂正——を、あなたのハーネス（スキル、指示書、ツール、コード）への変更案に変える [OpenCode](https://opencode.ai) v2 プラグインです。

エージェントは自分のセッションから学びません。どこでつまずいたかを知る唯一の方法はログを読むことですが、ログは誰も読みません。`opencode-retro` があなたの代わりに読み、提案を持って戻ってきます。

> **状態：端から端まで動作するが、まだ未リリース。** 収集・抽出・レビューはすべて実装済みで、OpenCode 2.0.32 上で検証済みです。npm にあるのは名前の確保用のプレースホルダーだけなので、当面はパス指定でインストールしてください。何があり何がないかは[ロードマップ](#ロードマップ)を参照。

## 問題

セッションごとに、エージェントは同じ壁にぶつかります。

- あるスキルが「リンターを実行せよ」と言う。しかしこのプロジェクトはリンターを使っていない。エージェントは実行し、40 ファイルを書き換え、間違いに気づいて、すべてを巻き戻す。
- 同じ失敗するコマンドが、試行の間に何も変えないまま 4 回繰り返される。
- 計画の中の一つのタスクが「今は無理です」として静かに落とされる。
- ユーザーが「いや、ここではそうやらない」と three 週目に入っても言い続けている。
- 20 ステップを節約できたはずのツールが、そもそも存在しない。

これらはすべてログの中にあります。そしてそのどれも、次のセッションには届きません。

## 何をするのか

意図的に分離された二つのループです。

### 1. 収集ループ — 自動、毎セッション

プラグインは、すべてのツール呼び出しとすべてのプロンプトについて軽量な**シャドーログ**を保持します（`.retro/sessions/<id>.jsonl`）。LLM は関与せず、追記のみです。これによりプラグインはセッション履歴の圧縮から独立し、生の軌跡は常に手元に残ります。セッションの抽出が成功すると、そのログは削除されます。物語は教訓そのものが運んでいますし、セッションごとのログを永久に抱えるのは、ただの溜め込みです。

モデルの前に検出器はなく、何を摩擦とみなすかという規則もありません。三つ試しました——試行の間に何も変わらないまま繰り返されたコマンド、取り消された編集、スキルが指示したコマンドがのちに失敗したケース——そして、それらが結果を変えるかどうかを**実測しました**。変えませんでした。同じログを与えたとき、モデルは検出器があってもなくても同じ教訓を見つけました（`fixtures/ab-anchors/`）。それらが実際に符号化していたのは検出ではなく、「何を見るべきか」という一つの見解でした。見解は、あなたが読み、異議を唱えられるプロンプトに属します。モデルが何に気づいてよいかを前もって決めるコードに属するものではありません。ですから、いまそれはそこにあります。`.retro/prompts/extract.md` が探す価値のある形を記述しています——何も生まなかった繰り返しの作業、取り消された編集、行き止まりまで付き従ったスキル、「completed」というステータスの裏に隠れた非ゼロの終了コード、静かに落とされたタスク、二度言わせてしまった訂正——そして、これは出発点であってチェックリストではないと明示しています。

セッションが終わるとキューに入り、**次のセッションの最初のプロンプト**がその負債を払います。クリーンなコンテキストでのモデル呼び出しが一度だけ走り（作業したエージェントではありません。自分の判断を弁護してしまいます）、ログの圧縮された射影を受け取ります。ツール出力は刈り込まれ、プロンプトと回答は全文です。答えるのは一つの問いだけです。

> *このセッションをもう一度やり直すとしたら、より短く、より真っ直ぐ進むために何を変えるべきか。*

出力は `.retro/lessons/` に置かれる**教訓**の一覧です。

なぜ今回のセッションではなく次回なのか。OpenCode の `generate.text` は呼び出しがフックの内側から始まったときにしか解決せず、セッションはイベントで終わります。ですから教訓は一セッション遅れて現れ、二度と開かないプロジェクトには何の費用もかかりません。`/retro` はその負債を要求に応じて清算します。

### 2. 統合ループ — 要求に応じて、`/retro`

プラグインはログを読みます。あなたは提案を読みます。プラグインは提案で止まります。あなたのファイルには手を入れません。

```
/retro         一つの教訓 — まだ未決のうちで最もスコアの高いもの
/retro auto    待機中のすべての教訓を、一度に承認できる一つの計画として
/retro check   プラグインが本当に動いているか
```

`/retro` は、あなたがそれを実行したセッションに教訓を届けます。すでにそこにいるエージェント宛のメッセージという形で届きます。

```
_opencode-retro: まず一つの問いに答えてください — これは、いまのこのワークスペースの状態で
すでに解決済みではありませんか。教訓は数週間そこに置かれていることがありますし、あなたは
このプロジェクトを知っています。普段どおりの方法で確かめてください。……人間が決めるまでは
何も変更しないでください。_

lint スキルは `npx eslint . --fix` を指示しているが、このプロジェクトではそれを実行できない。

2 セッションで確認、9 ステップを消費、確信度 0.9 → スコア 16.2。
最後に見られたのは 3 セッション前。

## 提案する変更
**AGENTS.md** — lint の要求を、コミット済みの ESLint 設定がある場合に限る条件付きにする。

## あなたの判断が必要
このプロジェクトは本当に ESLint を設定すべきか、それとも lint という約束事自体をやめるべきか。
```

そこから先は、あなたとエージェントが決めます。エージェントはファイルと履歴、そしてこのプロジェクト自身のスキルを持っています。その教訓がまだ成り立つかを判断する役としては、プラグインよりエージェントのほうが優れており、実際に主張を照合し、提案が見落としていた帰結を見つけます。決めたあとは、`retro_decide` ツールで結果を記録します——これは記帳だけです。却下は記憶され、その教訓は二度と提案されません。

`/retro auto` は、それを一度にまとめて行うものです。待機中のすべての教訓を順位づけし、まだ成り立つものだけを対象にした一つの計画を、ファイル単位でまとめて返します。プランモード向けです。計画を読み、一度承認して、進む。

教訓の提案は*示唆*であり、スキーマではありません。よくある宛先は次のとおりです。

- **skill** — その作業がここでは実際にどう行われるのかを、`SKILL.md` に修正・追記する
- **instruction** — `AGENTS.md` に加える事実または制約
- **tool** — 人間への依頼：「X がない。それがないためにセッション A・B・C はそれぞれ約 N ステップを失った」
- **refactor** — 罠そのものを取り除くコードベースの変更。理由を添えて。自動適用は決してしない
- **other** — どれにも収まらない。人間が決める

## 教訓の形式

```yaml
id: lint-skill-no-config
statement: The `lint` skill assumes eslint; this project has no linter.
evidence:
  - session: a81f
    steps: [41, 58]
  - session: c204
    steps: [12, 19]
cost: 34          # その問題が食べたステップ数、セッションをまたいで合算
recurrence: 3     # それが現れた独立したセッションの数
confidence: 0.9
lastSeen: 41      # 最後に現れたときのワークスペースのセッション通算数
recordedAt: 2026-10-19T15:16:04.134Z
proposal:         # 任意
  target: .opencode/skills/lint/SKILL.md
  change: |
    Before running: check for a lint config (eslint.config.*, .eslintrc*)
    and a `lint` script in package.json. If absent, do not run; report.
ask: Is the linter really unused here? Remove the skill from this project?
status: new       # new | later   （決まったものは archive/ へ移る）
```

スコアは `cost × recurrence × confidence × freshness` です。鮮度は、その問題が現れなかったセッションが十回続くごとに半減します。しかも**日数ではなくセッション数**で数えます。一日一セッションの使い方では、壁時計基準の減衰は一晩で何もかも埋めてしまうからです。再発は、一度の高額な事故より重要です。三つのセッションに現れた教訓は、四つめにも*現れます*。

教訓のスコープはワークスペースで、鍵になるのはセッションではなく**問題**です。同じことにぶつかった二度目のセッションは、二つめのファイルを作るのではなく、証拠を追記して `recurrence` を増やします。`lessons/` にあるのは未決の問いだけで、決定はファイルを `archive/` に移します。そして何も削除されません。いったん閉じたのに戻ってきた問題は、同じ問題であることに**加えて**、その直し方が持たなかったという知らせでもあるからです。履歴をそのまま保ったまま再び開かれます。上限（既定 30）が一覧を短く保ち、あふれた分も同じく保管されます。

## これは何ではないか

- **記憶プラグインではありません。** 記憶プラグインは、エージェントが問い合わせるのを忘れないでいなければならない知識ベースを作ります。`opencode-retro` は、ハーネスがすでに読んでいる成果物（`SKILL.md`、`AGENTS.md`）を編集します。スキルの中に住んでいる知識は、思い出す必要がありません。
- **ループ破りではありません。** ループ検出器は*いま*エージェントを止めます。このプラグインは、そのループが*次回*起きないようにします。両方を使ってください。
- **成功事例の収穫機ではありません。** 自己改善型スキルのツールはたいてい*うまくいった*ことを集めます。これは*うまくいかなかった*ことを集めます。安い勝ちはそこにあります。

## 教訓はローカル、直す場所はローカルかグローバル

教訓は常にワークスペースにローカルです。教訓とは一つのプロジェクトのセッションから得られた証拠なので、そのプロジェクトの中だけに住みます。グローバルな教訓の保管場所はなく、プロジェクト間で教訓が昇格することもありません。これは意図した設計です。

グローバルになり得るのは**直し方**です。摩擦の一部はこのリポジトリについてのものです。そこに合わないスキル、ここでは真でない `AGENTS.md` の記述。一部はリポジトリではなく、あなたがどこでもどう働くかについてのものです。課題管理ツールとの付き合い方、ブランチ名の付け方、プロジェクトをまたいで持ち歩いている約束事。前者はそのプロジェクトのハーネスに属し、後者はあなたのグローバルなハーネス——`~/.config/opencode/AGENTS.md` やグローバルなスキル——に属します。

ある教訓がどちらを求めているかは、引き渡しの瞬間に決まります。あなたとエージェントが、その教訓が実際に何を言っているかを見て決めます。プラグインは推測せず、あなたのグローバルなハーネスを自分の判断で編集することもありません。

## 設計上の判断

- **抽出は別セッションで。** 作業したエージェントは、自分のセッションを裁く者として最悪です。
- **セッション履歴ではなくシャドーログ。** すでに書き留めたものを、圧縮は食べられません。
- **成功よりも摩擦。** 巻き戻し、繰り返し、訂正はより稀で、「うまくいきました」よりずっと多くを語ります。
- **記憶よりも成果物。** ハーネスがすでに読むものを変える。覚えておくべきものを増やさない。
- **まず人間の関門。** 自律はあとの段階であり、それ自身の立証を必要とします。
- **提案で止まる。** あなたのセッションにいるエージェントは、ファイルと履歴と、このプロジェクトのスキルを持っています。*「これはまだ成り立つか」*と問うほうが、確かめ方をプラグインが指定するよりも優れています。

## インストール

npm にはまだプレースホルダーしかありません。`opencode.json` をチェックアウトしたディレクトリに向けてください。パスは**絶対パス**でなければならず、相対パスだとセッションの起動がエラーも出さずに固まります。

```jsonc
{
  "plugins": [
    {
      "package": "/abs/path/to/opencode-retro",
      "options": {
        // 必須：これがないと OpenCode は自身の無料枠を解決し、プラグインはそれを使えません
        "model": { "providerID": "deepseek", "id": "deepseek-flash" }
      }
    }
  ]
}
```

その他のオプションはすべて任意です：`dir`（既定 `.retro`）、`prompts`、`halfLife`（10 セッション）、`autoLimit`（`/retro auto` 一回あたり 10 教訓）、`maxOutput`、`extractTimeoutMs`、`keepSessions`。

プラグインが書くものはすべて、あなたのプロジェクトの `.retro/` 以下に入り、提案を受け入れた場合を除いて他のどこにも書きません。すべてプレーンテキストです。

```
.retro/
├── prompts/
│   ├── extract.md       # あなたが編集する — 何を教訓とみなすか
│   ├── review.md        # あなたが編集する — 教訓をどう引き渡すか
│   └── review-auto.md   # あなたが編集する — まとまりをどう一つの計画にするか
├── sessions/<id>.jsonl  # 原材料。抽出後に削除される
├── lessons/<id>.md      # 成果物
├── archive/             # 決定済みと押し出された教訓
├── selfcheck.md         # プラグインが動いているか
└── state.json
```

各プロンプトは初回実行時に同梱の既定値から種をまかれ、以後二度と書き換えられません。解決順はプロジェクト → `~/.config/opencode/retro/prompts/` → 同梱の既定値なので、あるプロジェクトだけに固定することも、すべてのプロジェクトに固定することも、どちらもしないこともできます。新しい既定値は `prompts/updates/<name>.vN.md` として届き、冒頭にそのファイルは使われていないと書かれています。あなたの代わりに適用されるものは何もありません。

ソースに残り、あなたが編集するものではないのは機械的な部分です。パーサーが必要とする出力形式（`/retro check` が印字します）、教訓のフィールドの順序、そして結果を記録せよという指示。解析可能な教訓を produce しなくなったプロンプトは静かに失敗します。そしてそれが、わざわざ設計で備えるに値する唯一の故障の仕方です。

### 動いているか

フックが登録できたことは何も証明しません。名前を間違えたフックは機嫌よく登録され、そして一度も発火しません。ですから `.retro/selfcheck.md` は「設定済み」ではなく「生きている」ことを主張します。イベントストリームとフックを突き合わせることで主張し、自分自身の鮮度の規則も携えています。

> いまあなたが作業しているのに `heartbeat` が数分より古いなら、このプラグインは動いていません。

`/retro check` は能動版です。`ctx` の表面、モデルへの接続性、いまどの層のプロンプトが有効か、そして実際の出力契約の往復。

## 必要なもの

- OpenCode **v2**（`@opencode/plugin` 2.0 以上。2.0.32 で検証）
- 抽出用のモデル。`options.model` に明示的に指定すること。安いもので十分です
- 実行時依存はありません
